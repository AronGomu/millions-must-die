Zombie Collision

Zombies stop passing through each other. Agent-agent soft separation steering in the fixed-tick sim: repulsion sum bends the flow-field vector, agent walks the blend at unchanged speed. Body radius is scenario data. Six commit-sized tickets. Index: PLAN_2026_08_08_zombie-collision.md.

In scope

  • Scenario gains collision_radius_q8 + separation_strength_q8
  • Zero-alloc uniform neighbour grid
  • Separation wired into sim::tick::step — always on
  • Deterministic tie-break for coincident agents
  • Two demo scenes: 10k mid-body, 1 200 sprite-accurate
  • Repair of the already-red merge gate
  • Systems map, close doc, ADR 009, architecture page

Out of scope

  • Hard non-overlap guarantee — model is steering
  • Renderer, sprites, shaders, goldens
  • Any performance number, anywhere
  • Agent-obstacle collision — already exists
  • New CLI flags — collision is data, not a switch
  • Combat, selection, camera

The forcing constraint

View 1920×1080 = 2 073 600 px. Sprite 30×30 = 900 px. Gate scene = 50 000 agents = 45 000 000 px of sprite → 22× the screen. Hex-packed 30 px discs on the free 80% top out near 1 700. So "50 000 agents" and "sprites never overlap" cannot both hold. Radius became scenario data; three tunings ship.

Ticket flow

Tickets

T1 Repair the red merge gate depends: none

The branch already fails. docs/02-prototype-roadmap.md was deleted into docs/CONTEXT.md; tests/validation_contract.rs still reads it and panics. Two tests down before a line of feature work. Repoint the const, delete the duplicate literal.

Commit outcome: cargo test --workspace --locked green again — the baseline every later ticket is measured against.

T2 Scenario collision contract depends: T1

Two u32 Q8 fields on ScenarioSpec and Scenario — integer because both derive Eq, exact in f32 because 256 is a power of two. Required, not defaulted: a stale scenario fails loudly. Five tracked .ron files edited, five sidecars regenerated. V1 locks its tuning like every other frozen constant.

Commit outcome: every scenario carries a body. Zero behaviour change — proven by a before/after state hash taken across a git stash.

T3 SpatialGrid neighbour bins depends: T2

Counting sort into buffers reserved at construction. Bin edge max(1.0, 2 × radius) so a 3×3 scan covers every contact. Buckets ascending by agent index — that is the determinism, not an accident of iteration. Out-of-rect and NaN coordinates clamp instead of panicking.

Commit outcome: the index exists, is tested, and provably allocates nothing. No caller yet.

T4 Separation wired into the tick depends: T3

The flip. v = flow + strength · Σ repulsion, renormalise, walk. Coincident agents get a 16-entry table direction keyed on (i ^ j) & 15, signed by i < j so a pair pushes equally and oppositely — 50 000 agents seed onto 127 spawn cells, so ~394 share one coordinate at tick 0. Eight neighbours max per agent, a correctness bound on that stack, not an optimisation. If the blended step is not walkable, retry the pure descent step: separation may never wedge an agent the field alone could have moved, which turns "no agent is stuck" from luck into structure.

Exactly one contract is re-derived. aggregate_progress_is_monotone → aggregate_progress_never_stalls: the mean cost is no longer monotone (a stack unpacking moves members backwards) but the horde must never go a full simulated second closing no distance. An explicit escalation rule forbids nudging any threshold — the one permitted remedy is halving the fixture radius, and if that fails, stop and report.

Commit outcome: zombies push each other apart on every tracked scenario. The gate-scene hash changes, deliberately and observably.

T5 collision_scene_v1 demo scenes depends: T4

A third version family: gate-scene screen geometry, free population and radius under a 20 000 cap. V1 freezes its 50k/100k workload; the fixture_ caps stop at 65 536 cells — neither can express a full-screen low-count scene. Both scenes ship as tracked assets with sidecars, plus a committed idempotent generator for provenance. No new --check gate.

Commit outcome: cargo run -- run --scenario assets/scenarios/collision_sprite_v1.ron shows 1 200 sprites that visibly keep off each other.

T6 Systems map, docs, ADR depends: T5

Collision becomes the twelfth named phase-0 system, enforced in both directions by every_system_has_a_test. MIN_SCANNED_TESTS is measured, not guessed. A new known-gap section says plainly what the model does not guarantee. ADR 003's "overlap allowed" line is struck and superseded in part.

Commit outcome: the claim is auditable, and the two demo scenes join the merge-gate smoke list.

Standing rules across every ticket

TDD, no exceptions

Red first, in every ticket. T1's red is the two already-failing gate tests. T2's red is a compile failure on fields that do not exist yet.

No silent weakening

No threshold nudged, no test #[ignore]d, no tick budget stretched to go green. T4 spells out the single permitted remedy and the stop-and-report line.

No perf claim

Performance gating is retired. A live doc stating a speed number fails no_perf_claim_in_docs. Collision cost is unmeasured and says so.

Frontloaded, T1

No package, account or key is needed anywhere in this plan. Two host facts are recorded up front instead: graphify is documented in AGENT.md but not installed here, so no ticket runs it; and the dev host has a GPU, so the gate runs with MMD_REQUIRE_GPU=1 and a skip counts as a failure.

The honest limitation

Soft steering was chosen over hard push and over an occupancy lattice. It buys smooth flow and a cheap deterministic pass; it cannot promise zero overlap. Under crowd pressure — most visibly in the destination jam, which is accepted behaviour — bodies interpenetrate. No test, comment or doc may claim otherwise.

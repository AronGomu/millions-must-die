Horde sim headroom

Two things, one branch: resize the game to StarCraft scale, and keep the headroom work in the per-agent, per-tick neighbour scan that resize makes hotter. No behavioural guarantee spent. Every capability is scenario data with an identity default, so a scene that does not opt in walks a bit-identical path.

Goal

First, resize the game. Decision of 2026-08-09: make the game feel closer to StarCraft — fewer entities, but bigger. The absolute simultaneous-entity ceiling becomes 5 000; sprites grow to 48 px with the body radius exactly half a sprite; every entity draws its own hitbox ring; the render layer moves to a 2:1 isometric projection with a real depth order.

Second, keep the headroom work. The resize makes the one loop that scales with agent count hotter, not colder — the body radius grows from 102 q8 to 1 536 q8. Five changes from the research backlog (.tmp/RESEARCH_they_are_billions_performance.md § C.8, items 1, 3, 5, 8, 9) land on top, all confined to crates/mmd-engine/src/sim/.

Success = T0 is the only ticket that moves a hash; every ticket after it keeps a bit-identical state hash on every tracked scene that does not opt in; every new simulation capability is scenario data with an identity default; the zero-allocation invariant still holds on every thread; and the merge gate is green after each ticket.

Scope

In

  • T0 · MAX_LIVE_AGENTS = 5_000; sprites 48 px; body radius exactly half a sprite; gate digest re-pinned once.
  • Three scenario knobs: separation_phases, mass_class_count, separation_threads — each identity 1, each bounded, each rejected on a bodyless scene.
  • 1 · amortise the scan and the grid rebuild over N ticks.
  • 5 · stamped bin counts; no per-rebuild clear; O(1) bin_count.
  • 9 (adapted) · row-contiguous scan + empty-window early-out.
  • 8 · per-agent push priority, so a goal sink breaks its own symmetry.
  • 3 · parallel separation on a persistent pool, bit-identical at any thread count.
  • T8 · a procedural hitbox ring, on by default, toggled with H.
  • T9 · 2:1 isometric projection with an alpha-tested-cutout depth order; the sim stays Cartesian.
  • Docs: ADR 010, ADR 011, ADR 012, architecture page, close-doc system map, glossary.

Out

  • Any performance number, anywhere. Perf gating stays retired; every ticket is accepted on behaviour.
  • Camera control. T9 ships a fixed view centred on the destination cell; scrolling, edge-pan, zoom and selection are Phase 1.
  • Flow field tiling, dirty flags, LOS pass (backlog 6 and 7) — Phase 1, when walls become destructible.
  • Flocking goal propagation (backlog 10) — needs targeting.
  • Retuning the fixture_* scenes — their arrival-tick constants are calibrated against their current bodies.
  • Any new third-party dependency. rayon is not added.
  • Hard non-overlap. Unchanged from ADR 009 — this is steering, and the bigger body makes overlap rarer and more visible, not impossible.

Ticket flow

Two sub-graphs share one root. T0 (the resize) feeds both the headroom sub-graph below (T1–T7, unchanged by the resize) and the render sub-graph (T8 → T9), and both T6 and T9 feed T7. Cheap and safe first: amortisation (T3) divides the same pass by a known factor with no new failure modes, so it lands before threading (T6), which brings false sharing, a shutdown path and a determinism surface to defend.

What each ticket proves

T0

StarCraft-scale cap and body

depends: none

MAX_LIVE_AGENTS = 5_000 enforced by one check_population call at the validator dispatcher. technical_prototype_v1 is retuned in place — same version id, new locked constants — rather than frozen behind a v2. Sprites grow to 48 px; collision_radius_q8 grows to exactly half that, so two touching bodies are edge-to-edge.

Proof: the gate smoke's hash= is re-pinned exactly once, and every ticket after T0 must reproduce it byte for byte. The four fixture_* scenes are deliberately left untouched.

T1

Scenario headroom knobs

depends: T0

Contract only. Three required fields on ScenarioSpec and Scenario, carried through CollisionParams so Simulation::new_custom keeps its arity. Seven .ron files edited, seven .sha256 sidecars regenerated. Nothing reads the values yet.

Proof: the two pinned digests pass unedited. Seven new rejection tests: zero, over-cap, bodyless-and-tuned, gate-scene-not-identity.

T2

Stamped bin counts

depends: T1

counts, count_stamp, stamp on SpatialGrid. The starts.fill(0) pass goes; the prefix pass reads zero for a stale bin and still writes starts for every bin, which T4 depends on. Wrap does one full clear.

Proof: bit-exact — BODIED_STACK_HASH unmoved. Bin counts match bucket lengths; a bin that empties reports zero; the wrap path is reachable through a testkit-gated hook.

T3

Amortised separation

depends: T1

Agent i recomputes when i % phases == tick % phases; the grid rebuilds on phase 0. Strided, not blocked — agent index correlates with spawn cell, and a blocked split would read as a wave crossing the horde. Reynolds ran 15 000 agents on a skipThink of 8 to 10.

Proof: one phase is the identity. A skipped agent's repulsion is unchanged until its phase returns; the grid rebuilds twice in eight ticks at four phases; an amortised stack still spreads; and the amortised scene still never enters an obstacle.

T4

Row-contiguous scan

depends: T2

Bin index is bx + by * cols and buckets are laid out in ascending index, so each row of the 3×3 window is already one run in items. Three slices instead of nine, identical agents, identical order. An agent alone in its window writes zeroes without touching items.

Proof: the row slice equals the bin-by-bin concatenation; the cap's break 'scan survives; BODIED_STACK_HASH unmoved.

T5

Per-agent push priority

depends: T1

Push on i from j scaled by mass[j] · inv_mass[i], reciprocal precomputed at construction. Froblins names the bug — agents pile at a small goal and cannot get out. StarCraft II's answer is asymmetry, not a better solver.

Proof: one class means every mass is 1 and every scale is exactly 1.0, so the digest cannot move. A heavier neighbour demonstrably pushes a lighter one harder, and two classes do move the digest — so it is not a no-op.

T6

Parallel separation pass

depends: T3, T4, T5

Persistent pool spawned at construction — never inside a tick, because creating a thread allocates. Two barriers, no channel. Participant w of T owns [w·n/T, (w+1)·n/T), so no partial sum crosses a boundary and no reassociation is possible.

Proof: identical state hash at 1, 2, 4 and 8 threads, run ten times. Zero allocation on every thread — workers arm the counting flag, so the invariant now covers them. Clean shutdown, no hang.

T8

Hitbox ring overlay

depends: T0

A ring at collision_radius_cells · cell_size_px, read from the live simulation rather than the scenario document. Procedural: a sentinel in uv_rect.x selects the shader's ring branch, so SpriteInstance stays pinned at 48 bytes and no fifth atlas is added. On by default, toggled with H, scriptable as --inject-input N:h.

Proof: a ring is packed for every agent and none for a bodyless scene; the ring traces the real body radius, including a body that is not half a sprite; ten new tests, zero new allocation.

T9

Isometric projection and depth

depends: T8

A 2:1 world→screen projection at the render layer only — the simulation stays in Cartesian cell space, so no pinned state hash moves. Depth is keyed off each quad's ground point, tested GREATER against a clear of 0, with sprite depth floored at one D16_UNORM quantum so a degenerate map cannot blank a frame. Alpha correctness comes from a clip() cutout, not a sort, so the 4-atlas batching survives. The camera is fixed, centred on the destination cell, with an AABB reject for off-screen quads.

Proof: git diff --stat crates/mmd-engine/src/sim/ is empty; instance_layout_is_stable unmodified; an agent in front occludes one behind and rings are never occluded; seven new tests, zero new allocation.

T7

ADRs, architecture doc, system map

depends: T6, T9

Verify ADR 010 and ADR 011 against what shipped, flip them to Accepted; author ADR 012 for the resize and render decisions; and map all 45 new tests into tests/validation_contract.rs and the close doc — in both directions, which is what makes the map unfakeable. SCOPE_SYSTEM_COUNT rises from 12 to 14: T8 and T9 each add a real system, T1–T6 do not.

Proof: every_system_has_a_test and no_perf_claim_in_docs green. The close doc is a live doc — every added line must dodge the banned perf tokens.

Two rejections worth reading before implementing

Backlog 9 does not apply as written

Ericson's min-corner 2×2 window works because each pair is enumerated once and contributes to both members. accumulate_separation is a gather — for agent i it must see every neighbour j — and a 2×2 window misses every j one bin lower on either axis. A symmetric scatter would write sep[j] from i's loop and destroy the index-disjointness T6 needs. T4 ships the transferable half, which is bit-exact where the 2×2 would not have been.

Backlog 5 cannot reach O(#agents) here

The prefix-sum pass over bins is structural to a counting sort; only the clear can go. Reaching O(#agents) needs a per-bin linked list — which destroys the contiguity T4 exploits — or a per-tick sort of touched bins. Neither can be settled by measurement, because measurement is retired. T2 ships the stamped form and earns its keep by giving T4 an O(1) bin_count.

What this plan does not claim

Nothing here has been measured on this engine, and no ticket passes or fails on a speed figure. Performance gating is retired for phase 0. The figures in the research dossier behind this plan are other people's published results, cited to attribute a mechanism, and they gate nothing.

Every acceptance criterion is behavioural: identity tunings produce bit-identical state hashes, the threaded pass produces the same output at every thread count, nothing on the tick path allocates on any thread, obstacles are still never entered, and the pool shuts down cleanly.

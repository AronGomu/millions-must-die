1. What is an enemy, in code?

Deepest fork of the phase — decides which store, which collision contract, which navigation, and how phase 3 (tens of thousands) later scales on top.

2. How does damage travel from weapon to target?

Decides the determinism surface, the render work, and whether a projectile is a simulated thing or a drawing.

3. Who fights in this slice? (additive — tick several)

Fixes the sprite, stat and test surface; every extra combatant kind is stats + sprite + card lines + audio receipts.

4. How deep is the damage model?

Every stat enters the state hash and the balance pass is explicitly out of scope — depth here is cost without payoff until the economy phase.

5. What is the turret?

First attacking building — placement, cost and footprint should ride the existing four placement rules unless you want a new rule class.

6. What does enemy AI do?

"No per-enemy pathfinding" stands — whatever the behavior, it must ride shared pooled flow fields (8 slots, LRU).

7. How do enemies enter the scene?

The gate script must be deterministic, so enemy arrival has to be scenario/contract data, not improvisation.

8. Which combat commands does the player get?

The command card is positional 3×3 (QWE/ASD/ZXC) — each command claims a slot, an executor path, and an audio receipt.

9. What happens at 0 HP — and can buildings die?

A dying building must un-stamp its footprint, which invalidates every cached flow field; a dying HQ touches drop-off and the defeat question.

10. Is there a defeat or victory state?

Phase 6 owns the mission framework — but if the HQ can die (Q9), something visible has to happen.

11. How is HP shown?

The overlay layer is texture-free by contract (rings + line instances) — a procedural bar fits it exactly; readability is a core pillar.

12. Where does combat live on the merge gate?

Phase-1 scripts, hashes and goldens are frozen contracts — combat needs enemies in a scene without moving any of them.
